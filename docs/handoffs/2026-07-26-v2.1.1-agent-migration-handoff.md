## 5. 产品行为必须符合的预期

### 5.1 用户请求

用户可以直接输入：

- “生成 4 张国风茶饮海报，比例 3:4。”
- “生成一个运动鞋广告主视觉，做 3 个版本，选择最有冲击力的一张，再生成 8 秒视频。”

Agent 应该：

1. 自动理解用户目标。
2. 先生成并在右侧展示可见的提示词和执行步骤。
3. 不要求每一步确认，直接继续执行。
4. 调用现有图片/视频生成链路。
5. 把每个结果作为正确类型的画布节点写回。
6. 失败时保留可重试状态，不阻塞其他已完成结果。

只展示可审计的状态摘要、提示词和步骤，不展示隐藏思维链。

### 5.2 Skill

- 入口只叫“我的 Skill”。
- Skill 在使用前已经配置好。
- 支持导入 Skill 或调用本地 Skill。
- 不提供“新建 Skill”。
- Skill 在输入框内选择，并随任务一起执行。

### 5.3 两条链路并存

- 画布底部悬浮输入框：快速、直接生成，保持现有行为。
- 右侧 Agent 输入框：多步骤、多结果、可恢复的自动执行。
- 两条链路复用现有模型配置和 API，不互相覆盖。

## 6. 正确迁移方式

### 阶段 A：确认 2.1.1 UI 基线

1. 在当前工作树运行 `git status`，确认没有切错目录。
2. 确认当前历史包含 checkpoint `948de81`。
3. 检查敏感信息，不提交 Key、素材和缓存。
4. 迁移前不要格式化全仓库，不做无关重构。

### 阶段 B：迁移 Agent 内核

优先移植以下不直接控制主 UI 的部分：

- `src/lib/canvas-agent/`
- `src/app/api/agent/`
- 对应测试
- Agent 所需依赖和 feature flag

可以按 Agent 提交逐个审查或选择性 cherry-pick，但每一步都要检查是否修改了 2.1.1 已改文件。

### 阶段 C：手工适配 Agent UI

`2dc1c60` 和 `af7868c` 属于 UI 密集提交，**禁止直接覆盖式 cherry-pick**。正确做法：

1. 复用 `src/components/canvas-agent/` 的任务逻辑和 assistant-ui runtime。
2. 把 UI 手工装进 2.1.1 当前右侧深色侧边栏。
3. 不恢复 Agent 分支里的旧布局、旧颜色或旧工具栏。
4. 不删除当前画布底部悬浮输入框。
5. 顶部入口开启 Agent 侧栏；关闭侧栏时任务继续运行，再打开可恢复状态。

### 阶段 D：写回与回归

- Agent 生成的图片必须进入图片画布节点。
- Agent 生成的视频必须进入视频画布节点。
- 结果尺寸、节点位置和连接关系要遵守当前 2.1.1 画布规则。
- 不能直接由 React 组件操作 tldraw，继续使用类型化画布命令桥。

8. 失败任务能重试或取消，不无限转圈。
