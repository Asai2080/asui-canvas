# Asui Canvas 2.1 Iteration Plan

## Principles

1. Do not break any completed 2.0 path.
2. Work only on branch `codex/asui-canvas-2.1`.
3. Apply first-principles decomposition before implementation.
4. Use adversarial review before marking a feature complete.

## Priority

### P0: Canvas Generation State

Status: completed.

Goal: when an image generation task is running, the related canvas node should show a clear in-canvas status layer.

Scope:

- Show the provided diagonal scan SVG animation while a holder, single-annotation edit, or multi-annotation edit is generating.
- Keep the animation as a React overlay above the canvas, not as tldraw document content.
- Clear the status layer on success or failure.
- Preserve existing image generation, annotation generation, multi-annotation generation, cutout, and size controls.

Acceptance:

- Creating an image holder and clicking Fill Image Holder shows the scan overlay on that holder while the request is in progress.
- Generating from a single annotation shows the scan overlay on the source image while the request is in progress.
- Generating from all annotations shows the scan overlay on the source image while the request is in progress.
- The overlay disappears after success or failure.
- The overlay respects `prefers-reduced-motion`.
- `npm run lint` passes.

### P1: Image To Video

Status: in progress.

### P2: Short Drama Pipeline

Status: planning only for 2.1, not implementation.

### P3: Codex Native Task Card

Status: in progress.

Goal: provide an ASUI-owned Codex card path for canvas generation tasks without copying or depending on third-party project naming or code.

Scope:

- Keep the existing standalone web canvas and API generation paths intact.
- Add a project-local Codex plugin manifest and MCP server for ASUI task cards.
- Render image, annotation-edit, and future image-to-video tasks as native Codex cards.
- Treat this as a generation-only workflow; it must not trigger code-change tasks.
- Do not copy third-party implementation code, file names, tool names, or product names.

Acceptance:

- The MCP server lists an `open_asui_canvas_card` tool.
- Calling `open_asui_canvas_card` returns a structured ASUI task card and a widget output template.
- The card can render either ad-hoc arguments or an existing `.asui-codex/tasks` task id.
- Existing web generation, cutout, image-to-image, video-node, and API config flows continue to work.
